\section{Related Work and Novelty Positioning}
\label{sec:related_work}

The transition of LLMs to autonomous enterprise agents makes tool context efficiency and execution reliability paramount. We situate LASR-MCP within four emerging paradigms in tool-augmented literature:

\noindent\textbf{1) Tool Retrieval in MCP}: Tool catalogs exhaust context windows as registries grow. RAG-MCP~\cite{rag_mcp2024} and MCP-Zero~\cite{mcp_zero2024} employ dense retrieval to filter catalogs, while Gorilla~\cite{patil2023gorilla} and ToolLLM~\cite{qin2023toolllm} retrieve APIs from large sets. \textit{Distinction}: These frameworks operate at the \textit{inter-tool catalog level} (which tools to load), whereas LASR-MCP operates \textit{intra-tool}, resolving parameter constraints once a tool is chosen.

\noindent\textbf{2) Schema Compression and Dense Representation}: Tool Attention~\cite{tool_attention2024} lazily loads parameter docs via intent gating. TSCG~\cite{tscg2024} compiles verbose schemas into dense interfaces, while LLMLingua~\cite{jiang2023llmlingua} and LLMLingua-2~\cite{pan2024llmlingua2} compress prompt tokens. \textit{Distinction}: TSCG changes the representation of the schema at the API boundary, whereas LASR retains native schema semantics and adaptively exposes/recomposes constraint nodes within an already selected tool while enforcing an empirically validated Invariant Foundation Floor ($C_I^*$).

\noindent\textbf{3) Field-Aware and Schema Routing}: SchemaRouter~\cite{schemarouter2024} predicts parameters, noting under-fetching risks, while HyperAgent~\cite{hyperagent2024} coordinates field pruning. \textit{Distinction}: LASR-MCP performs closed-loop recovery inside an active schema via \textbf{Dynamic In-Tree Recomposition ($C_R$)}, extracting omitted constraints from validator diagnostics to achieve complete structural recovery across evaluated cases.

\noindent\textbf{4) Execution Traces and Tool Adaptation}: ReAct~\cite{yao2022react} and Toolformer~\cite{schick2024toolformer} demonstrate self-correction, and ToolSpec~\cite{toolspec2024} uses speculative decoding. \textit{Distinction}: Standard trace recovery appends raw error strings to history; LASR-MCP intercepts validator paths for \textbf{in-tree AST recomposition}, splicing missing constraint subtrees directly into the schema on Attempt~2.

\noindent\textbf{Summary of Novelty}: LASR-MCP resolves constraints within an already selected tool schema, combining intent-conditioned proactive prediction with validator-derived in-tree recomposition.
